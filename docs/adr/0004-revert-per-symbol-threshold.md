# ADR-0004: 回退并移除分标的穿越阈值

- 状态：已接受
- 日期：2026-09-11

## 背景

momentum 策略的穿越阈值原为全局单值 `threshold_pct`。为提高各标的命中率，曾引入
分标的覆盖 `threshold_by_symbol`（如 ETH 0.10 / SOL 0.12 / 新标的 0.15），依据是
30 天扫描「高阈值 → 命中率更高」：

- ETH 0.08→80.6% / 0.10→84.1% / 0.15→89.1%
- SOL 0.08→75.6% / 0.12→81.8% / 0.15→85.3%
- XRP 0.08→72.9% / 0.15→80.6% | DOGE 0.08→73.4% / 0.15→82.4% | BNB 0.08→84.1% / 0.15→91.2%

2026-09-10 实盘：提高阈值后 **0 成交**。全部 35 笔成交（含 cap=0.50 时段的 18 笔）
都发生在全局 0.08。

机制：高阈值 = 信号更晚 = 盘口已从中性 0.50 跳变到 0.63+（1701 条拒单中
0.50–0.63 之间一条都没有）→ EV = q − p 中 p 涨得比 q 快 → 机会消失。
**原扫描按命中率优化，而实盘约束是成交率——目标函数选错了。**

## 决策

1. 回退为全局单值 0.08。
2. **删除** `threshold_by_symbol` 机制：字段（Config / StrategyConfig / DEFAULTS）、
   load 校验、`to_strategy_config` 映射、momentum 构造分支、多标的聚合面板的分标的
   展示一并移除；阈值收敛为单一 `threshold_pct`。

## 后果

- 阈值语义只存在于一处，不再有「升阈提高命中率」的误导性扩展点。
- 未来重新校准阈值时，**目标函数必须是成交率 / EV（q−p），不是命中率**；且需先
  证明存在「高阈值仍能成交」的盘口窗口（当前证据相反）。
- 若分标的差异确有依据，应以 `q−p` 分层数据重新论证，而非复用命中率扫描。
- `.scratch/threshold_tradeoff.py` 保留为复现脚本；本 ADR 为其结论的权威落点。
