# ADR-0002: TradeState 保留运行快照字段（面板字段不拆分）

- 状态：已接受
- 日期：2026-08-15

## 背景

架构审查建议将 TradeState 中"面板展示字段"（`predicting`、`predict_start_sec`、
`last_predict_sec`、`market_prices`）拆分出去，理由是领域状态与展示数据混合。

## 决策

**不拆分面板字段**。持久化（save/load/log_trade）已抽为 `StateStore`（ADR-0001 同批），
但 `predicting` 等四个字段保留在 TradeState 上。

理由：

- 这些字段是**随状态一起持久化的运行快照**：重启后面板需要显示"上次预测时间、
  推理中、最新盘口"，拆分后生命周期（设置 predicting 标记）与 monitor（读取）都
  要额外依赖一个跨进程传递的并行快照通道，复杂度反而上升。
- 语义上它们是"机器人运行状态"而非"交易决策状态"，但二者共享同一持久化生命周期
  （状态切换时原子落盘），分离的接缝收益不抵成本。

## 后果

- TradeState 仍含少量展示字段，接受其"领域状态 + 运行快照"的双重身份。
- 未来若出现多个展示源（如 Web 面板与 TUI 需要不同字段），再评估拆分——届时
  拆分的接缝应建立在 StateStore 之上，而非重新建议拆 TradeState 字段。
