## 1. 优化项(按价值排序)

### P1-1 凯利/半凯利分层仓位

- 文章依据: Kelly Criterion + Half Kelly(胜率估计有误差时仓位减半)
- 项目依据: BTC 同向组命中 84-87% / 未动组 80%(btc_cross_asset_signal.md)
- 方案: 转实盘后按条件胜率分半凯利仓位——BTC 同向 2x、未动 1x;
  当前固定 1 USDC 保留到统计 gate 样本(200+ 笔)足够
- 前置: 实盘余额读取(wallet.py)、每注规模参数化

### P1-2 auto_tune 多重比较纪律

- 文章依据: 多重比较问题 + 邦费罗尼校正
- 问题: auto_tune 按价格带统计调参,带内样本仅 n=2~6 即出决策;阈值类
  参数是从多组合扫描里挑的(threshold_scan.py),存在过拟合风险
- 方案:
  1. 参数冻结期: 实盘 200 笔前不调整 threshold/max_entry 类参数
  2. band 决策最小样本量: n >= 20 才允许改 max_entry(auto_tune.py 门槛收紧)
- 改动点: src/pmbot/auto_tune.py(min_band_n 与冻结逻辑)

### P1-3 同事件去重(组合层风控)

- 文章依据: 协方差——ETH/SOL 同向仓位风险不是简单相加(σ² = wᵀΣw)
- 项目依据: 9/6 09:20-09:50 五连亏(-3.09 区间),同窗口同向联动单是同一
  宏观动量的两份暴露
- 方案(极简版): 同窗口两标的同向信号,第二笔减半注或跳过;
  进阶版: 滚动 30 天 ETH/SOL 5m 收益相关系数作为联动度门控
- 改动点: run_multi 层(跨标的信号可见性)或 strategy 层(BTC 过滤器扩展)

### P2-1 波动率缺口门控(隐含 vs 已实现)

- 文章依据: MLE 反推("水坑反推降雨")——从合约价反推市场隐含波动率,
  与 Binance 实现已实现波动对比
- 方案: 5m 合约价 = 隐含概率;反推 MM 定价隐含的窗口波动预期,与
  Binance 秒级实现波动求差。缺口大 = MM 滞后大 = 机会大
- 好处: 替代"前窗口已实现波动 > X%"式经验阈值,给波动率门控定量形式
- 前置: 先让 measure_book_lag(.scratch/ 已有脚本)跑一晚,量化极化延迟
  与"信号时刻 ask"分布;数据到位后再定门控形态
- 改动点: strategy(momentum) 新增 refresh 前置条件 + config 新参数

## 2. 统计检验存档(可重复)

```python
# H0: 胜率 = 平均入场价(市场隐含);单尾二项
# 数据: data_multi/{eth,sol}/trades.csv
import csv
rows = [r for s in ('eth','sol') for r in csv.DictReader(open(f'data_multi/{s}/trades.csv'))]
n, wins = len(rows), sum(1 for r in rows if float(r['pnl']) > 0)
p0 = sum(float(r['entry_price']) for r in rows) / n
# 2026-09-10 实测: n=35, wins=26, p0=0.456 → p=0.0005 (通过邦费罗尼 0.05/20)
```
